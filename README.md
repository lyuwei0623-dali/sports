# 維大力體育APP V10

這是取代舊單一 `app.py` 的模組化版本。會員畫面提供三個功能：

- MLB 當日賽事分析
- 歐洲五大聯賽與歐冠分析
- MLB／足球走地情境計算機

會員頁只讀取已保存快照，絕不抓取外部 API、重跑模型或寫入資料。管理員輸入管理密碼後可直接進入後台，從後台建立自動快照、逐場輸入人工盤口，並發布人工正式版本。人工發布永遠優先於同日自動版本。

V9 的頁首以 Streamlit 原生圖片元件顯示根目錄的 `logo.png`，並顯示「維大力體育APP」；不再把圖片轉成 HTML／Base64，因此部署環境不會把品牌與防偽 LOGO 當成程式碼印在頁面上。

## GitHub／Streamlit 部署

1. 將這個資料夾內的「部署檔案」全部上傳到 GitHub 專案根目錄，並覆蓋同名舊檔。
2. GitHub 顯示變更後按 **Commit changes**。
3. 到 Streamlit Cloud 的 App 設定頁按 **Reboot app**，等待重新部署完成。
4. 到 **Settings → Secrets** 貼入下列設定，密碼與金鑰不要放進 GitHub：

```toml
APP_MEMBER_PASSWORD = "自行設定會員共用登入密碼"
APP_ADMIN_PASSWORD = "自行設定管理員密碼"
THE_ODDS_API_KEY = "The Odds API 金鑰"
API_FOOTBALL_KEY = "API-Football 金鑰"
FOOTBALL_SEASONS_JSON = '{"eng.1":2026,"esp.1":2026,"ger.1":2026,"ita.1":2026,"fra.1":2026,"uefa.champions":2026}'
```

`THE_ODDS_API_KEY` 與 `API_FOOTBALL_KEY` 是兩組不同服務的金鑰，不是 Streamlit、GitHub 或 APP 的登入密碼。

可選設定（沒有填寫時維持下列預設值）：

```toml
MLB_ODDS_REGIONS = "us"
FOOTBALL_ODDS_REGIONS = "eu"
```

不要把上述金鑰或設定直接寫進 `.py` 檔。若調整區域，請先在後台按「檢查資料連線」並建立一次自動快照，確認你的 The Odds API 方案確實提供該市場。

若暫時沒有 The Odds API 金鑰，MLB 後台仍會嘗試保存 MLB 官方完整賽程，但沒有可驗證市場盤的場次會如實標示 `PASS`。若 API-Football 金鑰或賽季未設定，足球後台仍會嘗試使用 ESPN 賽程備援；缺少的補強資料和盤口同樣會在賽表風險欄位中如實呈現。

## 每日操作方式

1. 以管理員密碼登入。
2. 在「管理後台」選當天日期。
3. 先按「檢查資料連線」，確認來源狀態；這個畫面不會顯示 API Key 或原始回應。
4. 在 MLB 或 Football 分頁按「立即執行自動快照」。
5. 成功後，會員端立即能讀到完整賽表。若沒有市場盤，賽事仍會顯示，但推薦會是 `PASS`。
6. 需要人工修正時，在同一運動分頁選比賽、逐格輸入盤口與賠率，再發布。發布後會員端會優先看到人工版本。

### 人工盤口輸入方式

- MLB：選單顯示繁體中文隊名，不顯示內部賽事 ID。讓分只輸入「主隊」一格：`-` 表示主隊讓分、`+` 表示主隊受讓；客隊讓分由系統自動反向。SUPER 特殊盤必須包含讓分基準，例如 `-1+85`、`+1-60`；單獨的 `+85` 沒有基準，不能安全結算。主／客香港賠率仍是未含本金水位。
- 足球：同樣只輸入「主隊」亞洲讓分一格，`-` 表示主讓、`+` 表示主受讓；支援 `-0.5`、`+0.5`、`-0/0.5`、`+0.5/1`，客隊盤自動反向。大小分與 1X2 十進位賠率照原方式輸入。

### MLB 自動盤口的原則

建立 MLB 自動快照時，系統先以 MLB 官方賽程確認主客隊，再將 The Odds API 的即時 `h2h`、`spreads`、`totals` 價格對應到該場比賽。常見的隊名縮寫（例如 `LA Dodgers`、`NY Yankees`）會安全地對應回官方隊名，避免真實價格因名稱不同而漏掉或套到另一隊。

- 只有可驗證、未過期的即時價格才會送進既有模型計算。
- 僅顯示既有 +EV 門檻通過的推薦；未通過時顯示 `PASS`。
- 如果來源只提供獨贏，系統只評估獨贏；不會自行假設或補造 -1.5／+1.5 讓分價格。
- 你日後手動輸入 SUPER 盤並發布時，人工版本照舊覆蓋當天自動版本。

### 足球自動盤口的原則

足球先使用 The Odds API 的可驗證市場。若某一個具有 API-Football fixture ID 的賽事未成功對應到有效市場，後台才會使用同一個 API-Football 帳戶的賽前盤口補強該場；它仍需通過既有亞洲盤／大小分驗證後才會送進原本的 Poisson 與 +EV 運算。後台會顯示「來源、可用、對應、已運算、達 +EV」的安全摘要，不顯示原始回應、URL 或金鑰。

## 重要資料保存提醒

此版預設把快照存到 `data/` 下的 SQLite。Docker／VPS 會透過 `docker-compose.yml` 把這個資料夾掛載成持久資料；請不要刪除它。

Streamlit Community Cloud 的本機檔案並非永久資料庫。測試可以使用，但部署重啟、休眠或系統清理後，已保存快照可能遺失；若要立即給會員長期使用，至少要在每次重啟後重新建立當日快照，正式營運前應換成有持久磁碟或外部資料庫的主機。

## 不變的運算邊界

- MLB Base Model、SUPER 特殊盤拆分與 +EV／結算規則沒有改寫。
- Football 亞洲盤拆分、+EV 門檻與結算規則沒有改寫。
- 這次只改善盤口來源配對、人工校正介面、來源診斷與會員端呈現。
- 走地計算機是手動輸入賽況的原版情境試算，不會自動抓取直播資料，也不列為已驗證的正式推薦。
